# Si3217x rev C map: RAM/register names, init write list, LCQCUK configuration, presets

Collected 2026-11-14. Read-only research, nothing on the device or LAN was
touched. Companion to `si3226x-facts.md` (same directory); it fills the
Si3217x gaps that file left open (its sections 4.6 and 7 item 9).
Everything is described in my own words. No code and no patch data words are
reproduced. Numbers are addresses, bit positions and configuration constants.

In running text a RAM location is written `NAME (address)`, address in
decimal; "rev C" after the address means the name comes from the rev C
header. Addresses were inserted by script from the parsed headers, not typed.

### 1.2 RAM map (Si3217x rev C)

Source: CREG enum `SI3217X_COMM_RAM` (1168 names, addresses 0..1596)
merged with RREG enum `SI3217X_REVC_RAM` (209 names, addresses
15..1644). The two enums do not overlap: the common header simply leaves
out the addresses whose meaning depends on the revision. 1377 rows.
Addresses 1024 and above are memory-mapped registers and need user mode.
Names of the form UNUSEDnnn / GENERIC_n are the header's own placeholders.
Addresses missing from the table (for example 1024..1083) are not named by
either header.

One alias defined outside the headers: REVC line 67 gives GENERIC_8 (1522)
the name DCDC_DCFF_ENABLE (it is not used by the rev C code paths I read;
rev C uses DCDC_LIFT_EN (1635, rev C) for the "dcff" drive instead). INTF lines 74-75
name two patch-owned RAM cells, VBATH_NEON = 995 and LCRMASK_MWI = 987,
used only by the message-waiting functions and only meaningful with the
patch loaded.

## 2. Ordered init write list, rev C

Call chain in the public driver: the application calls a reset helper, then
`Si3217x_Init_MultiBOM(preset)` (copies row `preset` of the multi-BOM table
over the single general configuration, MBOM/INTF 1113-1125) or
`Si3217x_Init`, both of which end in `Si3217x_Init_with_Options`
(INTF 1149-1441). "GC.x" below means member x of the general configuration
(section 3). Steps marked **[P]** are patch steps.

Init options (INTF 1161, 1269, 1372, 1395): INIT_REINIT skips steps 2..5;
INIT_NO_PATCH_LOAD skips steps 6..8; INIT_NO_CAL skips steps 10 and 12.
The source comments say single-channel devices must always reload the
patch and recalibrate.

### Step U: user mode helper (used throughout)

`setUserMode` (INTF 199-228). Turn on: read reg 126 TEST_CNTL; if bit 0 is
already 1 do nothing; otherwise write 0x02, 0x08, 0x0E, 0x00 to reg 126 in
that order.
**In this version the "off" request returns immediately without touching
the chip (INTF 203-204).** So once any step has switched user mode on it
stays on for the rest of the session; every `setUserMode(FALSE)` in the
sequence below is a no-op.

### 2.3 Longitudinal balance calibration (separate call)

`Si3217x_LBCal` (INTF 1597-1708): remember ENHANCE and LINEFEED; power-save
off (ENHANCE and 0x27); LINEFEED = 1 (forward active); CALR0 = 0x0F;
CALR3 = 0x80; then read CALR3 and wait 10 ms repeatedly until bit 7 clears,
limit TIMEOUT_LB_CAL = 2410 passes (about 24 s). On timeout LINEFEED is
set to 0 (open) and an error returned, otherwise LINEFEED is restored;
ENHANCE is restored in both cases. The line must be on-hook.

Results can be read or reloaded under user mode at CMDAC_FWD (1476),
CMDAC_RVS (1477), CAL_TRNRD_DACT (1458), CAL_TRNRD_DACR (1459) (INTF 1725-1851). Note the
name is CMDAC_RVS here (CMDAC_REV on Si3226x), same addresses. The packed
form stores bits [25:18], [24:17], [20:13], [20:13] of the four values in
one 32-bit word (shifts 6, 1, 5, 13 with byte masks; INTF 1757-1851).

### 2.4 Soft re-init

`Si3217x_Reinit` (INTF 1483-1503): remember LINEFEED; power the converter
down (2.2); wait 10 ms; reg 1 RESET = 0x01; wait 100 ms; run the init with
the INIT_REINIT option (skips steps 2..5 only: the patch is loaded again
and all calibrations run again); write the remembered LINEFEED value back.

### 4.3 Impedance (Zsynth) preset

`Si3217x_ZsynthSetup` (INTF 2426-2506). Sequence:

1. Remember LINEFEED, write LINEFEED = 0.
2. Write the coefficient set in this order: TXACEQ_C0 (540), TXACEQ_C1 (541),
   TXACEQ_C2 (542), TXACEQ_C3 (543), RXACEQ_C0 (546), RXACEQ_C1 (547), RXACEQ_C2 (548),
   RXACEQ_C3 (549), ECFIR_C2 (563), ECFIR_C3 (564), ECFIR_C4 (565), ECFIR_C5 (566),
   ECFIR_C6 (567), ECFIR_C7 (568), ECFIR_C8 (569), ECFIR_C9 (570), ECIIR_B0 (571),
   ECIIR_B1 (572), ECIIR_A1 (573), ECIIR_A2 (574), then ZSYNTH_A1 (656), ZSYNTH_A2 (657),
   ZSYNTH_B1 (654), ZSYNTH_B0 (653), ZSYNTH_B2 (655) (this order, which is not the
   order of the structure: the structure holds b0, b1, b2, a1, a2), then
   reg 45 RA, then TXACGAIN (544), RXACGAIN_SAVE (906), RXACGAIN (545) (both from the
   rxgain member), RXACHPF_B0_1 (658), RXACHPF_B1_1 (659), RXACHPF_A1_1 (660).
3. Gain plan: recompute the TX and RX gain/equaliser values for the
   preset's txgain_db / rxgain_db (both 0 in every public preset) and
   write them again through the audio-gain routines (4.4).
4. Impedance calibration: CALR0 = 0x00, CALR1 = 0x40, CALR2 = 0x00,
   CALR3 = 0x80; then read CALR3 and wait 1 ms repeatedly until bit 7
   clears, at most 500 passes. Reason given in the source: needed when
   on-hook transmission is used and no off-hook event has triggered the
   automatic calibration.
5. Restore LINEFEED. Returns a calibration timeout error if the 500
   passes ran out.

### 4.4 Audio gain presets

Structure (PH 340-347): acgain, mute, aceq_c0..c3. CONST lines 81-84 hold
two working slots: slot 0 (TX) acgain 0x1377080, slot 1 (RX) acgain
0x80C3180, everything else 0. These are scratch slots that the gain
computation overwrites before they are loaded.

| Call | Writes | Source |
|---|---|---|
| TX gain setup (slot n) | TXACGAIN (544) = acgain; TXACEQ_C0 (540)..C3 = aceq_c0..c3 | INTF 2539-2551 |
| RX gain setup (slot n) | RXACGAIN_SAVE (906) and RXACGAIN (545) = acgain; RXACEQ_C0 (546)..C3 = aceq_c0..c3 | INTF 2560-2574 |

Gain computation used by the impedance preset (INTF 4207-4440), whole dB
steps from a table of 10^(dB/20) x 1000 (the high-resolution 0.1 dB
variant is a build option, disabled in CFG): the preset's base value is
divided by 1000 (integer) and multiplied by the table entry; the
equaliser coefficients are sign-extended from bit 28 first. Where the
gain is placed: TX attenuation goes into the TXACEQ coefficients, TX gain
(up to the normal maximum) into TXACGAIN; RX attenuation into RXACGAIN,
RX gain into RXACEQ. At 0 dB the factor is 1000, so the result is the
preset value with its last three decimal digits truncated (value / 1000 x
1000), not the exact preset value. The mute member is not used by these
routines; muting is DIGCON bits 0 (RX) and 1 (TX) (INTF 2007-2032).

### 4.5 PCM preset and time slots

`Si3217x_PCMSetup` (INTF 2760-2889), narrowband case:

1. reg 44 DIGCON: read, clear bits 2 and 3 (high-pass filters enabled).
2. Write 26 band-filter coefficients (literals in the driver, identical
   for every narrowband preset): TXACIIR section 1 (B0, B1, A1), sections
   2 and 3 (B0, B1, B2, A1, A2 each) at 518..530, and the same layout for
   RXACIIR at 550..562. Values in address order,
   TX: 0x3538E80, 0x3538E80, 0x1AA9100, 0x216D100, 0x2505400, 0x216D100,
   0x2CB8100, 0x1D7FA500, 0x2CD9B00, 0x1276D00, 0x2CD9B00, 0x2335300,
   0x19D5F700;
   RX: 0x6A71D00, 0x6A71D00, 0x1AA9100, then the same ten values as TX
   sections 2 and 3.
3. reg 47 ENHANCE: read, clear bit 0 (wideband off).
4. reg 11 PCMMODE = pcmFormat or (pcm_tri shifted left 5) or (alaw_inv
   shifted left 2). Format codes: 0 A-law, 1 mu-law, 3 16-bit linear.
   This write clears bit 4, so PCM is disabled until PCM start.
5. reg 13 PCMTXHI: read, keep bits 1:0, or in (tx_edge shifted left 4),
   write.

Wideband presets instead load wideband TXACIIR/RXACIIR values plus the
TXACHPF/RXACHPF sets and set ENHANCE bit 0; refused on Si32171/Si32172
(INTF 2769-2770). The source warns that the impedance preset overwrites
some RXACHPF values, so in wideband the PCM setup must come after it.

Time slots, `Si3217x_PCMTimeSlotSetup(rxcount, txcount)` (INTF 2896-2915):
reg 12 PCMTXLO = txcount low byte, reg 13 PCMTXHI = txcount high byte,
reg 14 PCMRXLO = rxcount low byte, reg 15 PCMRXHI = rxcount high byte. Counts
are in PCLK periods from frame sync. **The PCMTXHI write is the plain
high byte, so it clears the TX_EDGE bit (bit 4) that the PCM preset may
have set.** With tx_edge = 0 in all public presets this does not matter;
it would if tx_edge = 1 were wanted (then write the slots first).

PCM start / stop (INTF 3598-3640): read PCMMODE, set / clear bit 4.

### 4.6 Hook state and interrupts

* Hook state (`Si3217x_ReadHookStatus`, INTF 3091-3101): read
  reg 34 LCRRTP; bit 1 set means off-hook.
* Interrupt read (`Si3217x_GetInterrupts`, INTF 2933-3090): read
  reg 18 IRQ1, IRQ2 (19), IRQ3 (20), IRQ4 (21) in that order; in SPI mode
  reading clears them (GCI builds write the value back to clear). Bit
  layout (HDR 341-378), bit 0 first:
  IRQ1: OSC1_T1, OSC1_T2, OSC2_T1, OSC2_T2, RING_T1, RING_T2,
  FSKBUF_AVAIL, VBAT.
  IRQ2: RING_TRIP, LOOP_STAT, LONG_STAT, VOC_TRACK, DTMF, INDIRECT,
  TXMDM, RXMDM.
  IRQ3: P_HVIC, P_THERM, PQ3, PQ4, PQ5, PQ6, DSP, MADC_FS.
  IRQ4: USER_0..USER_7.
  Same layout as Si3226x.
* Interrupt enable (`Si3217x_EnableInterrupts`, INTF 2046-2065): IRQEN1..4
  (regs 22..25) = GC.irqen1..4. On rev A only, IRQEN1 is masked with 0x7F
  and IRQEN3 with 0xC0 (comment: the VBAT measurement is broken on rev A).
  Disable (2080-2109): write 0 to all four, then read IRQ1..4 once to
  clear.
* DTMF digit: reg 60 TONDTMF low nibble (INTF 3649 onwards, not transcribed).

### 4.7 Line feed state, ringing, polarity

* Set line feed (`Si3217x_SetLinefeedStatus`, INTF 3108-3130): write
  reg 30 LINEFEED = requested state (0 open, 1 forward active, 2 forward
  OHT, 3 tip open, 4 ringing, 5 reverse active, 6 reverse OHT, 7 ring
  open; PH 370-377). Then:
  if the new state's low nibble is 4 (ringing): read IRQEN1 and write it
  back with bit 7 cleared (VBAT interrupt off while ringing);
  otherwise, on any revision other than A: read IRQEN1 and, **only if it
  is non-zero**, write it back with bit 7 set. (So with IRQEN1 = 0, as in
  the public and stock configurations, IRQEN1 is never changed; but if any
  IRQEN1 bit is enabled, the VBAT interrupt gets switched on as a side
  effect of every non-ringing line feed change.)
* Ring start = set line feed 4; ring stop = set line feed 1 (INTF
  3480-3515).
* Polarity reversal / wink (`Si3217x_PolRev`, INTF 3150-3183): first
  power-save off (ENHANCE and 0x27; comment: reversal and wink are not
  possible in low-power mode, and the routine does not turn power-save
  back on), then reg 31 POLREV = bit 0 abrupt, bit 1 reversal on; wink start
  = 6, wink stop = 4.
* Power-save (`Si3217x_SetPowersaveMode`, INTF 5229-5250): disable =
  ENHANCE and 0x27; enable = ENHANCE or 0x10.
* PLL free-run (INTF 3674-3722): start = ZCAL_EN 0x00 then ENHANCE bit 2
  set; stop = ENHANCE bit 2 cleared then ZCAL_EN 0x04; status = ENHANCE
  bit 1.

### 4.8 Power alarm handling

What the public driver does when a line-driver power alarm (IRQ3 bit 0,
P_HVIC) or thermal alarm (IRQ3 bit 1, P_THERM) is seen in the interrupt
read (INTF 3013-3020, 3078-3088, `isReinitRequired` 406-436):

1. It reports the interrupt to the caller like any other.
2. It additionally reads LINEFEED and, with user mode on, RDC_SUM (1499). If
   RDC_SUM bit 22 (0x400000) is set **and** LINEFEED has neither bit 2
   nor bit 6 set (mask 0x44; that is, neither the requested nor the
   actual state is one of states 4..7), the call returns "re-init
   required" instead of the interrupt count. The comment calls this an
   improper ring exit that can corrupt the DC feed state.
3. The caller is then expected to run the soft re-init (2.4), which
   restores the line feed value seen on entry; the comment there says that
   after an alarm this is likely the open state.

Nothing else is automatic: the driver's error hook is empty and carries a
"to do: recover from power alarm" remark (INTF 955-962). No code rewrites
LINEFEED after an alarm; putting the line back into service after the
chip has dropped to open is left to the application. There is no handling
at all for the PQ3..PQ6 bits beyond reporting them.

## 5. Si3217x-specific cautions found in the source

1. **Reg 74 is DIAG3 on rev C, not DAA_CNTL.** Comment at INTF 321-325:
   setting DIAG3 bit 0 sets PD_GR909, which powers down the line driver
   (HVIC). The rev A/B DAA probe sets reg 74 bit 0, so the revision must
   be checked first; the code skips the probe whenever ID bit 1 is set.
   A from-scratch driver must never write reg 74 bit 0 on this chip.
   (`Si3217x_SetDAAEnable` likewise refuses anything but a rev B Si32178,
   INTF 5263-5290.)
2. **No device-key guard in the Si3217x code.** The Si3226x driver refuses
   to run with a general-configuration key outside its range
   (`si3226x-facts.md` section 4 step 7). In the 7.3.2 Si3217x sources the
   device_key member (0x71 public LCQCUK, 0x73 the other multi-BOM rows)
   is not referenced by any function (searched all of INTF, REVC, the rev
   B helper and `proslic.c`). So nothing in this public version stops a
   wrong table from being applied to the converter.
3. **Converter short-circuit rule** (2.2 step 13): VBAT below half of
   VBATH_EXPECT 50 ms after the digital start means shut down with
   PD_DCDC = 0x300000 and disable the channel. The header comment of the
   routine lists the intent: digital start with over-voltage clamp and
   shutdown, delay, verify no short by looking for half the target, clear
   status, switch to the analog loop with clamp only.
4. **Open line before converter start** (INTF 470-471): LINEFEED is forced
   to 2 and then 0 first; power-save is switched off for the duration.
5. **Drive polarity and charge pump depend on bom_option, gate-driver
   option and the per-channel invert flag** (2.2 steps 6-8). For LCQCUK
   without gate driver: DCDC_SWDRV_POL = 0, charge pump on, 20 ms settle,
   dcff/lift drive off. The rev C comment says designs "may or may not use
   a gate driver, depending on the hardware"; the choice flips the
   polarity. An unknown bom_option makes the rev C setup refuse to start
   the converter.
6. **LCQCUK current threshold is doubled** (2.1 formulas): because of the
   0.2 ohm sense resistor on that reference design. If the HT802 board
   uses a different sense resistor the public numbers do not transfer.
7. **Rev C calibration masks differ from rev B**: CALR1/CALR2 = 0xC0/0x18
   (rev B 0xFF/0xF8) (HDR 35-39).
8. **Low-power ringing is requested differently on rev C**: RINGCON bit 7
   set and bit 6 cleared, USERSTAT 0, instead of USERSTAT = 1 (4.2 row
   17).
9. **Rev C always gets a patch in this driver.** There is no patch-free
   branch: rev B and rev C select a patch, any other revision aborts.
   No comment anywhere in INTF or REVC says what rev C does without the
   patch. The two "patch parameter" RAM cells 987 and 995 used by the
   message-waiting lamp functions only have meaning with the patch
   loaded.
10. **User mode is never switched off** by this version (step U). The
    whole runtime therefore operates with user mode on. A driver that
    does switch it off must switch it on again before every access to
    addresses of 1024 and above (ring preset DCDC_RNGTYPE, LB calibration
    results, RDC_SUM, PD_DCDC and so on).
11. **Init does not stop on a converter failure**: after a failed
    power-up the channel is flagged disabled and skipped by the second
    calibration, but the post-calibration writes are also skipped for it
    (they test the enable flag), so ENHANCE/AUTO stay at the bring-up
    values 0x00/0x2F. The converter has by then been shut down by the
    power-up routine itself.
12. **VBATR_EXPECT clamp**: ring presets cannot raise the ringing battery
    above the general-configuration value (110 V in the LCQCUK table).
13. **Wideband ordering** (PCM setup after impedance preset) and the
    **PCMTXHI/TX_EDGE overwrite** by the time-slot call: see 4.5.
14. **Rev A only**: VBAT interrupt and most IRQ3 bits are masked (VBAT
    measurement broken). Not relevant to rev C but explains the masks.
15. Patch loader remark (INTF 889-890): for broadcast loads on revisions
    below code 3 the patch RAM address must be rewritten before every
    word. Single-channel loads rely on auto-increment.

## 6. Not determined / open

1. **bom_option numbering versus the stock module.** `si3226x-facts.md`
   6.3 decodes the stock Si3217x row as "bom option 3". In public 7.3.2
   (and 7.0.2) code value 3 is the plain quasi-Cuk tag and LCQCUK is 5;
   with value 3 the public rev C converter setup would refuse to run and
   the current-threshold doubling would not apply. So either the stock
   API version numbers the enum differently or the earlier decode needs
   rechecking. A stock RAM dump settles it: DCDC_OITHRESH (1548) reads
   0x01C00000 with the LCQCUK doubling, 0x00900000 without (my
   arithmetic from the 1850 mA value).
2. Which ring table, impedance set (X or Y) and PCM preset the stock
   firmware loads: not derivable from the public files.
3. The mirror's preset names (CINC) and preset tables (CONST) are guarded
   by the same macro with opposite sense for the ring and impedance sets;
   which pairing a real build used is unknown. Values are reported as
   found.
4. Meaning of individual bits in RINGCON, DIAG3 (beyond bit 0),
   PCLK_FAULT_CNTL, PD_BIAS, PD_HVIC, PD_SWDRV and the PD_DCDC value
   encodings: only the values written and the source comments are known.
5. What rev C does without the patch: no statement in these sources.
6. The patch's support-RAM list and data were deliberately not
   transcribed (see `si3226x-facts.md` 4.1 and 4.3 for counts and
   identity with the stock blob).
7. Tone, FSK/caller-ID, DTMF, pulse metering, message-waiting, PSTN
   check and line-monitor functions were skipped as requested.
8. Reset timing for this board (the 250 ms values are the generic
   helper's, not a chip minimum).
